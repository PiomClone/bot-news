# RSS-поток новостей + топ-5

## Кратко

- Текущий дайджест не трогаем: он как раньше собирает выжимку 2 раза в сутки.
- Добавляем отдельную новую часть: постоянный RSS-поток новостей.
- Новая часть периодически делает fetch RSS, схлопывает дубли, сразу публикует уникальные новости в live-канал и обновляет пост, если та же новость пришла из другого источника.
- Реакции Telegram считаются по опубликованным постам. Раз в сутки топ-5 уходит в отдельный канал.

## Поток работы

- По расписанию `@every N minutes` запускается fetch для источников нового RSS-потока.
- Каждая новая RSS-статья сравнивается с уже найденными story-группами за окно времени, например 24-48 часов.
- Если это новая тема, создается story-группа и сразу публикуется пост в live-канал.
- Если это дубль существующей темы, новая ссылка добавляется как источник, а опубликованный Telegram-пост редактируется.
- Если эвристики не уверены, вызывается AI, который отвечает: та же новость или нет.

## Основные изменения

- Добавить отдельные таблицы/модели для новой части:
  - потоки/настройки RSS-потока;
  - источники RSS-потока;
  - story-группы;
  - источники внутри story-группы;
  - опубликованные Telegram-посты;
  - агрегированные реакции.
- Добавить конфиг:
  - включен ли RSS-поток;
  - live Telegram channel ID;
  - top-5 Telegram channel ID;
  - период fetch;
  - cron для ежедневного топа;
  - окно дедупликации.
- Добавить `NewsStreamService` отдельно от текущего дайджеста.
- Расширить Telegram-нотификатор:
  - отправка поста с возвратом `message_id`;
  - редактирование поста по `chat_id + message_id`;
  - прием `message_reaction_count` и запись суммы реакций.

## Дедупликация

- Сначала быстрые эвристики:
  - одинаковый canonical URL;
  - очень похожий title;
  - близкое время публикации;
  - совпадающие ключевые сущности/слова.
- AI вызывается только для спорных кандидатов.
- Если AI недоступен:
  - сильные эвристические совпадения все равно схлопываем;
  - спорные новости считаем отдельными.

## Топ-5

- Раз в сутки берем опубликованные story-группы за период.
- Сортируем по сумме всех Telegram-реакций.
- Публикуем 5 лучших новостей в отдельный канал.
- Помечаем период как опубликованный, чтобы не отправить повторно.

## Тесты

- Миграция БД создает новые таблицы и индексы.
- Дедуп:
  - одинаковый URL схлопывается;
  - похожий заголовок попадает в AI-проверку;
  - разные новости не склеиваются.
- Публикация:
  - новая story-группа отправляет один новый пост;
  - дубль редактирует старый пост;
  - ошибка редактирования не ломает состояние БД.
- Реакции:
  - `message_reaction_count` мапится по `chat_id + message_id`;
  - рейтинг считается как сумма всех реакций.
- Регрессия:
  - старый дайджест продолжает работать без изменений.

## Допущения

- Старая часть и новая часть не пересекаются по состоянию и логике отправки.
- Для v1 используем текущий RSS fetcher и текущий Groq/OpenAI-compatible AI.
- Telegram-библиотеку пока не меняем: сначала пробуем `telebot.v3`, потому что нужные типы reaction update уже есть.
- Рейтинг простой: любая реакция дает 1 балл.
